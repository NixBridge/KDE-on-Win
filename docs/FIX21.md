# Fix21：稳定性排查与累计交付修复

本轮以项目现有集成代码、启动入口和累计补丁清单为审查范围，没有扩展登录或全局换肤的权限范围。没有逐行审计 Qt/KDE 全部上游源码，也不把自动化通过视为 VM 验收。

## 确认并修复的问题

### 启动、Shell 与历史补丁遗漏

- **历史累计包遗漏启动入口。** 对照原始 VM 包和 Fix20 ZIP，确认 Fix20 没有 `deploy-vm.cmd` / `session-shell.cmd`；原始安装脚本也没有原生会话宿主入口。Fix21 明确覆盖这两个脚本，修复“代码已更新但 VM 收不到”的问题。
- 启动脚本直接采用当前构建前缀 `D:\KDE\CraftRoot` 和安全的 FOR 变量展开，完整包与累计包使用同一份源文件，移除完整打包脚本中的第二套文本转换。
- 原生会话宿主严格解析参数，未知、拼写错误或混用参数返回错误，不会误启动桌面。部署入口也拒绝未知操作和多余参数。
- 后台进程只继承显式列出的标准输入、输出句柄；不再继承启动器的其他可继承句柄。统一后台服务和主会话的启动实现，保留 cmd 脚本所需的特殊引用方式。
- 无法创建日志时重定向到 NUL，继续无控制台启动；进程等待失败会返回失败。保留缺脚本、创建失败、已配置 Shell 退出后的 Explorer 回退。
- Shell 切换不再先结束 Explorer 再尝试创建会话。创建失败时保留当前桌面并恢复原配置；冷启动尚未看到 Plasma 进程时保留 Explorer。看到进程不代表桌面已就绪，实际切换仍列入 VM 测试。
- 结束进程时校验会话编号和可执行文件完整路径，避免旧的按镜像名 taskkill 波及其他会话或其他目录中的同名 D-Bus 等程序。watchdog 检测也限制到当前会话。
- watchdog 启动服务不再经 cmd 展开路径，避免路径里的 `%`、`&` 和中文被错误解释；Shell 切换和换肤宿主的消息循环正确处理 GetMessage 错误。

### 托盘与通知

- 托盘和换肤宿主使用会话内单实例对象防止并发重复启动；托盘对象重复启动直接返回，避免重复创建接收窗口、监听和计时器连接；停止时撤销 SNI 服务、监听、图标记录和子窗口状态，重复停止安全。
- SNI 注册失败时断开专用总线连接；延迟断开连接不再依赖托盘宿主对象存活，桥接删除也绑定自身生命周期。
- WM_COPYDATA 拒绝空载荷，复制对齐后解析；提示文字按 128 字符上限读取。未知消息、未注册图标的 MODIFY 不再生成空条目。
- 隐藏状态遵守 dwStateMask；非空 GUID 不再仅按 Data1 判定；设置图标版本时使用 GUID 映射后的真实键。
- 移除高频层级维护中的重复刷日志；计时器只连接一次。
- 通知授权回调和快照投递通过可失效的接收器门控，销毁和跨线程排队互斥；退出后返回的授权结果不会访问已销毁界面。退出时回收工作线程对象，并配对工作线程的 WinRT 初始化。

### 控件、COM 与登录组件

- 原生控件画刷按需创建；最后一个状态的回调退出后清理两种配色的画刷，避免无样式线程的额外分配和控件销毁后的资源滞留。清理发生在正常 UI 回调中，不依赖 DLL 卸载回调。
- 换肤宿主只有在自身控制窗口创建成功后才安装 Hook；消息循环出错或外部 WM_QUIT 时同样撤销 Hook 并广播恢复。
- 音量组件仅对成功的 COM 初始化调用 CoUninitialize，避免 STA/MTA 模式冲突时破坏调用线程已有的 COM 状态。
- 静音和音量变化都通知 iconName，修复静音按钮状态变化后图标可能不更新的问题。
- 开始菜单扫描和 UWP 激活配对 COM 初始化计数，包括 S_FALSE，避免重复扫描累积引用。
- 登录提供程序传播用户计数失败，防御成功返回空用户指针；重复 Advise 先取得新引用再释放旧引用。合成用户数组测试覆盖失败和空对象，没有扩大支持的账户类型或登录场景。

## 自动验证

运行入口：`python tests/run_regressions.py --runtime D:/KDE/CraftRoot`。运行记录写入 `work/fix21-test-results.json`，截图与隔离设置留在 `work/fix21-validation-*`。其中三个原生窗口检查仅操作自身隐藏测试窗口。

- 受影响的 x64 组件和 x86 控件 / 宿主均重新编译。
- 49 项检查，包括现有 41 项和新增托盘、Shell 参数、音量 COM、异步通知销毁、独立通知总线、日志失败、累计入口及构建依赖检查。
- 句柄隔离测试按内核对象身份判断，避免把子进程中复用的句柄数值当成意外继承。
- 发布清单记录测试退出码、PE 导入依赖检查、累计 ZIP 哈希、CRC 及逐文件一致性结果：`manifests/fix21-validation.json`。
- 没有运行真实 Plasma 会话、全局换肤 Hook、关联安装、登录注册、系统更新或通知授权。

## 已知限制与 VM 待测试

1. **真实登录未验收。** 本地账户提供程序仍是实验功能；Windows 自带密码、PIN、Hello 提供程序保留。先保留快照和恢复入口，再测试安装、登录、失败、卸载和回退。
2. VM 必测：手动启动、安装为 Shell、退出 Plasma、模拟 Plasma / 服务崩溃、脚本缺失或前缀错误，以及切回 Explorer。冷启动保留 Explorer 的策略属于恢复保护，不保证实时隐藏它的所有 UI。
3. 在双屏、不同 DPI、负坐标屏幕、分辨率切换和任务栏位置变化下，复测标题覆盖、最大化恢复、菜单焦点、托盘点击坐标与桌面层级。隐藏窗口测试不能替代这些场景。
4. 跨进程 32/64 位控件注入、管理员窗口和受保护进程的表现仍需 VM；自绘标题栏、WinUI/XAML 与任意第三方客户区没有通用替换能力。
5. 当前运行时仍有编译前缀约束；超长路径、非标准安装布局和不同 Windows 版本不能据此宣称全面兼容。Shellswitch 的部分发现路径仍使用较短缓冲区，本轮没有扩大路径重构范围。
6. 音频默认设备热切换 / 拔插仍需实机或 VM 测试；本轮只验证 COM 生命周期和图标绑定，没有改变系统音量。通知 API 在异常提供方下的等待时间、蓝牙查询退出也没有故障注入验证，不宣称已完全解决。
7. SNI 删除沿用既有延迟释放策略；高频增删和托盘重启需在真实 D-Bus 负载下压力测试。合成测试不构成无竞态证明。

## 使用累计包

保留原始 VM 基础包，重启 VM，解压 Fix21 覆盖原 CraftRoot，然后运行 `deploy-vm.cmd`。Fix21 覆盖 Fix1–Fix20 的已有文件，并补齐历史遗漏入口；无需逐个安装旧补丁。不要在运行中覆盖 DLL。
