# Fix14：桌面层级与最小化标题栏

本包是相对于原始 VM 包的累计覆盖包，包含 fix1–fix13 的全部文件。重启虚拟机，将 ZIP 内容覆盖到原有 CraftRoot，再运行 `deploy-vm.cmd`。

## 桌面遮挡

旧实现依赖 Qt 的激活事件排队将桌面降到底层；这不能可靠地阻止原生层级变化。现在桌面 HWND 在 `WM_WINDOWPOSCHANGING` 中将请求约束到底层，禁止随之激活、禁止连带提升 owner。`WM_MOUSEACTIVATE` 保留鼠标点击，但不激活桌面。显示时清除意外的 owner 和 topmost 状态。此规则只用于桌面壁纸窗口，面板和菜单不受影响。

这次修复针对“应用仍在运行，但像全部最小化一样消失，点击桌面又恢复”的遮挡路径，不依赖禁用显示桌面小部件。此前禁用危险 Peek 最小化路径的补丁仍包含在累计包内。

## 最小化瞬间的原生标题栏

外部程序的 KDE 标题栏是独立工具窗口，Windows 的 DWM 最小化快照不会包含它。因此，对接管了标准标题栏的窗口单独设置 `DWMWA_TRANSITIONS_FORCEDISABLED`，使最小化/恢复立即完成，避免动画中露出原生标题栏。没有全局修改 Windows 动画设置，自绘标题栏程序不接管。

最小化期间保留接管对象，只隐藏绘制层，避免清理周期撤销策略。关闭装饰服务或取消接管时恢复 Windows 默认动画。该 DWM 属性不能读取原值，因此恢复的是默认启用状态，无法还原其他工具此前对同一窗口设置的禁用值。

## 验证范围

`desktop-stacking-probe.exe` 在不可见的测试窗口中，实际发送置顶、普通提升、移动和鼠标激活请求，检查桌面约束生效且其他窗口没有最小化。装饰自测覆盖 DWM 设置成功、最小化对象保留、恢复按钮和自绘标题栏排除。测试不启动宿主机 Plasma，也不操作用户窗口。

虚拟机仍需人工确认：打开多个应用，反复点击面板空白、任务按钮、桌面和菜单；检查应用不会被壁纸遮挡。分别通过 KDE 按钮和程序原有快捷键最小化/恢复，检查没有原生标题栏闪现，并复测最大化、混合 DPI 和多显示器。
