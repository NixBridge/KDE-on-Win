# Fix18：扩展客户端换肤与登录集成

累计覆盖包包含此前全部补丁。重启测试 VM，将内容覆盖 CraftRoot，再运行 `deploy-vm.cmd`。新增实验模块均由用户在 VM 中单独启用；宿主机测试没有安装全局钩子或登录提供程序。

## 项目应用的对话框统一

项目 Qt 样式现强制使用非原生文件、颜色、字体和消息对话框，并将 KDE 标题栏扩展至 QDialog。确认框等不具备最小化/最大化动作的对话框保留这一限制。窗口原有的确认、取消和模态行为由 Qt 处理。

Windows 必须呈现的 UAC、默认应用确认和安全登录外框仍是系统界面。第三方应用的原生文件对话框不由 Qt 属性控制。

## 登录后的原生会话宿主

新增 `kde-session-host.exe`。在 VM 执行 `deploy-vm.cmd install` 后，当前用户 Shell 优先指向此宿主；验证成功后由它在无控制台环境启动会话脚本。后台服务也通过原生助手启动，输出保存在 `%LOCALAPPDATA%\plasma-win-session\logs`，不再依赖露在桌面上的控制台窗口。会话脚本缺失、启动失败或异常退出时尝试回退 Explorer。

重复安装会保留首次 Shell 备份；备份、写入和恢复改用 Unicode 安全的注册表操作，避免含空格、中文或 `&` 的路径被命令解释器错误拆分。`deploy-vm.cmd restore` 仍用于恢复原会话 Shell。此设置与登录磁贴的安装相互独立。

## 传统 Win32 控件模块

在 VM 运行 `apply-client-style.cmd`，启动 64 位和 32 位后台服务；也可在“系统设置 → 外观”启动或停止。

模块通过当前桌面的 Windows 消息钩子，在窗口所属 UI 线程接管传统控件。覆盖普通按钮、复选/单选框、分组框、原生输入框/静态文本的配色，以及标准列表/树控件的背景与文本色。遵循项目浅色/深色、强调色设置，保留程序自己的字体和布局。

Qt、Chromium、XAML 等已知自绘根窗口与自绘按钮不套用这套 GDI 绘制。不同权限等级、受保护应用、第三方自绘内容不保证覆盖；管理员程序的客户区换肤尚未做 VM 验收。它不是通用 WinUI/XAML 主题替换器。

停止与恢复：`apply-client-style.cmd restore`。服务卸载钩子，并请求已接管窗口撤销子类和恢复列表原色。为保证现有窗口回调地址有效，已进入进程的绘制 DLL 会保持加载到该进程退出，但撤销后不再接管绘制。进程没有接收恢复消息时，可关闭并重开该应用。

后台模块默认不随会话自动启用，以便先完成 VM 兼容性验收。启用后“外观”中的实验性控件选项可控制是否绘制。后台监听设置文件更新，并通知已接管窗口刷新配色。

## 真正登录界面集成

新增独立的实验性 V2 凭据提供程序，为本地账户提供 KDE 品牌登录磁贴和密码输入流程。它没有重绘整个登录页面，也未替代系统 PIN/Hello。安装、恢复、支持范围和 VM 验收见 [LOCAL_LOGON.md](LOCAL_LOGON.md)。

## 验证

自动测试包括：32/64 位隐藏 Win32 控件绘制、复选状态与撤销；Qt 四类对话框标题和原生策略；合成登录凭据的打包/解包；只读安装计划和脚本语法；此前的桌面、图标、主题、Konsole、归档与关联回归。实际跨进程换肤、真实账户登录均待 VM 人工验收。
