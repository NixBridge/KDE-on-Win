# Fix22：Windows 交互与日常桌面功能

以已提交的 Fix21（04bf5eb）为基线，开始时工作区干净。保留历史补丁，继续使用现有 Plasma、FolderModel、TaskManager、原生启动器和 Qt 样式；没有启用实验性登录，也没有引入新的外部依赖。

## 确认的问题与严重程度

| 程度 | 代码或测试确认的问题 | 处理 |
| --- | --- | --- |
| 高 | 会话总线启动超时后仍返回成功，后续服务继续启动；watchdog 可一直尝试重启失败组件 | 传播失败到 VM 入口，保留原生宿主的 Explorer 回退；每个受监控服务最多连续重试三次并退避，不会仅因进程暂时存活而补充预算，关闭桌面后才重置；重定向日志回退 UTF-8 WriteFile，避免 WriteConsole 在文件句柄上静默失败 |
| 高 | 通知服务重启时，旧异步回复中的 ID 可能被新服务复用；旧清理可能关闭新通知 | 给通知条目标记服务世代，丢弃跨世代回复；独立 D-Bus 测试重现并验证此场景 |
| 中 | 面板提升到置顶层后缺少外部全屏应用的降层路径 | 按面板所在显示器的物理范围判断，排除 Shell 和普通最大化窗口（包括移除了标题栏的 Breeze 窗口）；全屏时降层，离开后恢复；处理面板 HWND 重建 |
| 中 | Windows 任务后端一律声称能最小化、最大化和关闭，并关闭分组 | 根据样式和原生系统菜单判断能力，操作前验证窗口与记录的 PID；仅对当前运行时中身份明确的 KDE 应用启用既有分组 / 关闭分组，不终止后台进程 |
| 中 | 通用 AppId 只用文件名，同名不同路径的应用可能被分到一起 | 普通应用用完整路径区分，只有当前运行时目录中的已知 KDE 应用使用对应 desktop ID |
| 中 | 多屏 ScreenGeometry 用逻辑坐标原点乘 DPR，混合缩放下可能定位到错误屏幕 | 改为 Windows 显示设备名称映射 QScreen；实际混合 DPI 仍待 VM |
| 中 | 除中日韩外的输入法布局统一显示 EN，布局名称和目标窗口状态可能过期 | 读取 Windows 的语言代码与本地化名称，同时刷新名称；切换前核对 PID/线程；动态读取布局列表 |
| 低 | 系统设置只有 network 定位入口，桌面菜单无法直接进入显示或外观页 | 增加明确的页名映射；非法页名留在默认页，加入 UI 检查 |
| 测试问题 | 新工具的离屏中文截图出现方框，字符串检查无法发现 | 测试进程显式加载 Windows 字体，新增中文字形覆盖断言并复查截图；不修改系统字体 |

## 新增与增强

### 桌面右键菜单

复用 FolderModel 的现有 QMenu、刷新动作和位置处理，在空白区域菜单加入：

- 刷新桌面 / 视图。
- 显示设置：进入本项目设置的显示页。
- 个性化设置：进入外观页。
- 在 Konsole 中打开终端：传递当前桌面目录。
- 剪贴板历史与桌面工具。

缺少启动器时禁用对应动作。保留现有文件、文件夹、粘贴等菜单，没有创建第二套右键窗口。新增菜单文本支持中文，并按项目语言设置或 Windows UI 语言选择。

### 任务栏窗口菜单

沿用 Plasma 原有菜单及 TaskGroupingProxyModel：最小化、最大化、恢复、关闭、关闭分组由原生窗口能力决定。关闭分组仅针对当前运行时中身份明确的 KDE 应用，只给对应普通窗口发送关闭请求，应用仍可显示保存提示；不杀进程。第三方应用和共享宿主未取得可靠的窗口应用 ID 时保留单窗操作，不按 EXE 猜测关闭全部；不同目录的同名程序也不会借用本运行时的 KDE 身份。

窗口操作后安排一次短延迟状态刷新，同时保留既有两秒标题 / 状态刷新和事件驱动的窗口增删。没有增加窗口枚举轮询。跨进程焦点权限、实时分组和关闭全部的真实表现仍需 VM 验收。

### 桌面工具、运行与快捷键

入口：开始菜单中的“桌面工具与剪贴板”、桌面右键菜单、系统设置的“关于与诊断”，或 `start-desktop-tools.cmd`。

`plasma-desktop-tools.exe` 在本次用户会话中单实例运行；普通重复启动转交给现有实例。IPC 仅允许当前用户访问，使用有长度上限的命令，不传剪贴板内容。快捷键绑定 GUI 线程，不依赖可重建的主窗口 HWND；注销时释放。

默认替代快捷键为 **Ctrl+Alt+Shift** 配合：

| 键 | 操作 |
| --- | --- |
| E | 打开 Dolphin |
| R | 项目运行对话框 |
| D | 显示 / 恢复桌面 |
| V | 剪贴板历史 |

可在工具窗口改为 Ctrl+Alt。两组含 Alt 的组合都可能与 AltGr 或应用内本地快捷键冲突；注册 API 无法发现所有应用本地冲突，遇到冲突可退出工具注销快捷键，并使用菜单或原生 Windows 快捷键。注册失败会在窗口提示不可用的键，不安装键盘 Hook、不反复抢注。Meta+E/R/D 保留 Windows 行为，不能宣称已可靠接管。[微软说明 Windows 键组合为系统保留](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)。

运行框接受可执行文件与参数，提供启动失败提示，不解释 cmd 运算符；Shell 内建命令或重定向请用 Konsole，原生 Win+R 仍保留。

显示桌面按系统菜单 / 工具窗口标志识别普通应用，兼容移除原生标题栏的 Breeze 窗口，排除 Plasma、Shell、工具窗及已最小化的窗口。使用异步窗口请求，恢复仅针对本工具标记的 HWND/PID；窗口销毁会移除标记，退出时尝试恢复。受更高完整性权限保护的窗口不会被强行操作；这不是对原生 Win+D 的完整替代。

### 内存剪贴板历史

当前上游构建明确排除 Klipper，因此新增小型 Qt 文本历史，未假称 Klipper 已可用：

- 默认仅保存本次运行的最近 20 条文本，可设 1–200 条，每条最多 65,536 个 UTF-16 码元。
- 去重、查看、Enter / 双击 / 按钮重新复制、手动清空、关闭记录时同时清空历史；清空历史不等于清空当前 Windows 剪贴板。
- 对所有 KDE passwordManagerHint（包括空值或 NUL 填充）保守忽略，尊重Windows 排除监控格式及 CanIncludeInClipboardHistory=0；格式异常时保守忽略。含本地文件 URI 的混合 MIME 也不作为文本收集，普通网页 URL 文本可保留。
- 不把历史写入配置、日志或 IPC，不声称能识别所有密码，也不承诺内存取证级擦除。Windows 自己的历史 / 云同步仍由原生设置控制。
- 不主动采集启动时已有的剪贴板内容，仅响应数据变化通知；重新选择带内部标记，避免更新循环。关闭记录时不取文本载荷。监听只连接一次，界面隐藏时不重建历史列表，预览只处理有限前缀；最小化后再次打开会恢复窗口。

隐私格式依据：[微软剪贴板格式说明](https://learn.microsoft.com/en-gb/windows/desktop/dataxchg/clipboard-formats)。实际第三方程序的原生格式交互仍需 VM；自动化使用合成 QMimeData，没有读取宿主机剪贴板。

配置读取错误时默认禁用历史，写入失败会提示本次更改可能无法持久保存。窗口关闭按钮和 Esc 隐藏界面；“退出桌面工具”结束组件并清空 RAM 历史、注销快捷键。会话入口在 Plasma 退出后请求空闲清理；后台模式另有启动等待上限及桌面进程消失检查，防止异常退出后长期遗留。`--stop-if-idle` 在没有现有实例时直接返回，不启动新监听器。工具允许系统注销 / 关机请求，在确认会话结束后清理；自动化只合成调用本组件消息处理，真实系统注销仍待 VM。强制结束进程会跳过析构，已最小化窗口可能需要用户从任务栏恢复，未宣称此情形能自动恢复。

### 通知

Windows 桥接通知默认请求 8 秒自动消失，服务端策略可能调整该时间；退出时关闭已知通知。保留动作回调、替换、关闭和原生通知历史，不删除 Windows 原始通知，也不承诺替换通知中心。真正的 KDE 应用通知仍由既有 Plasma 通知组件处理。

## 编译与验证

- 实际重编 x64 原生应用 / 输入法组件，以及 taskmanager.dll、plasmashell.exe、folderplugin.dll。x86 源码未改，本轮没有重编；运行了已有 x86 控件自测。
- `python tests/run_regressions.py --runtime D:/KDE/CraftRoot`：57 项，包括 Fix21 的 49 项、剪贴板模型、英文 / 中文工具 UI、私有 IPC 的重复初始化 / 超长输入 / 清理、输入布局标签、设置页定位和隐藏 HWND 窗口操作。
- 窗口测试只操作自身隐藏父窗口下的 HWND；全屏策略另外检查负坐标及普通最大化的几何判断，不能等同于全屏游戏实测。
- 通知测试启动独立临时 D-Bus，验证默认超时、动作、关闭、替换、取消及服务重启后的延迟回复；不申请 Windows 通知权限。
- 静态累计入口检查验证新组件交付和总线失败传播。没有在宿主机实际启动失败桌面、修改关联、切换 Shell、注册热键或启用登录提供程序。
- 从固定 SHA-256 的上游归档重新提取并严格应用全部补丁，新增补丁对应的 7 个编译源码文件逐字节一致。见 `manifests/fix22-source-verification.json`；发布检查见 `manifests/fix22-validation.json`。
- 保留少量上游弃用 API / 宏警告，没有把编译成功当作零警告或 VM 通过。

## 未完成与限制

**可选应用会话恢复本轮未实现，默认不启用。** 现有启动器没有可靠的受管理应用存活记录；在不保存敏感参数、不恢复提权程序、不重复启动的约束下需要额外生命周期设计。按本轮允许的成本取舍，优先完成上面的功能与修复，没有新增盲目扫描进程 / 重放命令行的替代实现。

仍有编译前缀和 Windows 版本限制；特殊虚拟目录保留原生 Shell 回退。未对远程共享、拖放、休眠、音频热切换、权限边界或所有程序的自绘窗口做完整验收。实验性本地登录及 Shell 替换继续可选、可撤销；不修改受保护系统文件。

## VM 手动验收清单

1. 原始快照覆盖 Fix22：普通启动、重复启动、缺 D-Bus / 缺 DLL、启动超时、关闭 Plasma、结束后台宿主、切回 Explorer；确认失败有日志且 watchdog 不无限重试。
2. 桌面空白右键：刷新、显示页、个性化、Konsole 工作目录、历史工具；切换主题、不同 DPI / 负坐标屏幕，检查弹出位置与焦点。
3. 多窗口应用：分组、标题 / 图标变化、最小化 / 最大化 / 恢复、禁用关闭、关闭分组后的保存提示；分别从不同目录运行同名程序，确认不误分组。
4. 单屏 / 双屏全屏、跨屏全屏、Alt+Tab、显示器插拔及分辨率改变：面板给全屏让层，退出后恢复，仍压住 Explorer 任务栏；不覆盖启动器和托盘弹窗。
5. 快捷键默认组合及冲突：打开后隐藏 / 重开工具，确认 HWND 重建不丢快捷键；切换修饰键、退出、重复启动及桌面异常退出时检查注销和残留进程。
6. 剪贴板：纯文本、Unicode、长文本、文件复制与拖放、KDE 和 Windows 的明确敏感标记、连续快速复制、重新选择、清空、禁用 / 启用；进程重启后历史应为空。
7. DE / FR / EN / 中文输入布局：前台应用与面板之间切换、目标关闭和重建、AltGr、IME 组合输入、时区和区域格式变化；不要只验证标签。
8. Windows / KDE 通知：自动消失、点击、主动关闭、应用退出、通知权限撤销、kded / Plasma 通知服务重启及重复投递。
9. Dolphin：本地盘、UNC 共享、驱动器根目录、中文 / 空格 / 百分号路径、桌面快捷方式、协议选择器和双向文件拖放。网络和权限失败应保留明确错误 / 原生回退。
10. 若另测实验性登录，先保留快照与 Windows 原生登录方式，再检查安装、失败、卸载和恢复；本轮自动测试没有真实登录结果。

## 累计包使用

重启 VM 后，将 Fix22 覆盖原 CraftRoot，再运行 `deploy-vm.cmd`。包含 Fix1–Fix21 的全部有效覆盖文件，无需逐包安装。不要在组件运行中覆盖 DLL。新桌面工具默认随本次 KDE 会话启动；会话恢复和实验性登录不会因此启用。
